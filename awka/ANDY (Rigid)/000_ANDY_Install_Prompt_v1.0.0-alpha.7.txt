0. PURPOSE
======================================================================
This 000 prompt is the installation directive for the patched ANDY Domain
Runtime v1.0.0-alpha.7 file set.

This reissue preserves the alpha.7 behavioral contract and corrects the
activation publication defect discovered during AWKA v1.0.0-alpha.4 activation:
AWKA alpha.4 rejected the first alpha.7 candidate registry set because ANDY
published a first-class event_registry, while AWKA alpha.4 accepts only its fixed
Definition Registry set.

The correction is architectural, not semantic: ANDY retains canonical Event
Registry semantics internally, but AWKA-alpha.4 activation publishes Event
Registry definitions as an Event Registry Catalog projection inside
schema_registry.

3. PATCHED ACTIVATION-PUBLICATION RULE
======================================================================
For AWKA v1.0.0-alpha.4 activation, ANDY must publish only the AWKA alpha.4
fixed candidate Definition Registry set:

entity_registry
capability_registry
validator_registry
renderer_registry
workflow_registry
tool_registry
schema_registry
policy_registry

ANDY must not publish a first-class event_registry to AWKA alpha.4.

Instead, ANDY publishes:

schema_registry["ANDY.SCHEMA.EVENT_REGISTRY_CATALOG"]

This projection contains all canonical Event Registry definitions and preserves:

- event identity;
- event definition count;
- Capability events_emitted contract resolution;
- ANDY.VAL.EVENT_CONTRACT behavior;
- runtime Event Record semantics through ANDY.ENTITY.EVENT_RECORD.

The projection is required specifically because AWKA v1.0.0-alpha.4 has a fixed
publication registry set and rejects unknown first-class registry names during
atomic activation publication.
